# Spike: Mixture-of-agents for hunts (not only disprove)

**Date:** 2026-09-22
**Issue:** [#68](https://github.com/EndsHunter/VulnForge/issues/68)
**Status:** Recommendation **A** — sequential multi-perspective inside one hunt lease
**Proof:** `vulnforge/stages/hunt_moa.py` + `tests/test_hunt_moa.py` (merge never emits `confirmed`)

## Decision

Extend mixture-of-agents diversity into **hunt** the same way dual disprove works: **one leased `hunt` task, sequential perspective slots, then a pure merge/rank of candidates**. Merge writes **candidates for `validate_mech` only**. Human-only confirm is unchanged.

Do **not** add a second hunt task kind, a join/merge lease, or a rewriter that stays on a single investigation pass.

This spike lands the library + tests. The live sequential loop stays **off** (`stages.hunt_moa: false`). Jonathan owns merge of this PR.

## Why A fits `harness.db` / leases

Today:

- `vulnforge/db.py` `lease_next_task(..., max_parallel=1)` — `BEGIN IMMEDIATE` + cap on `state='leased'`.
- `config/default.yaml` `run.max_leases_parallel: 1` (Settings: Max concurrent agents). Campaign harnesses (`default-campaign.yaml`, `quick-smoke.yaml`) also pin 1.
- One leased `hunt` already owns the cell: `stages/hunt.py` runs one area×class investigation, may enqueue **child** hunts on split / `continue_hunt` / shallow-none requeue, then `upsert_coverage_fact` + `insert_finding(..., state="candidate")`.
- Dual disprove already proved the sequential-slots-in-one-lease pattern: `resolve_disprove_verifiers` → sequential chats inside **one** `validate_llm` task → `aggregate_disprove_verdicts`. Never confirms; demote/reject only.

A hunt MoA that **mirrors that pattern** keeps:

| Constraint | How A satisfies it |
|------------|--------------------|
| Default lease cap = 1 | Perspectives share the already-held lease. No extra `lease_next_task` calls. |
| One coverage write per cell | `upsert_coverage_fact` / sink coverage stay at the **end** of the leased hunt, after merge. |
| Child hunts (split / continue / shallow requeue) | Unchanged: children are new queued `hunt` tasks, not sibling leases of the same cell. |
| Confirm honesty | Merge emit state is hard-coded `candidate`. HITL / Report remain the only `confirmed` writers. |
| Wall clock | Sequential slots cost more tokens/time **inside** the existing `lease_ttl_seconds` (default 1800). Same trade as dual disprove. |

Raising `max_leases_parallel` for other reasons (operator Settings) does not require a different hunt MoA shape. A still works at N>1: each hunt lease still runs its own sequential perspectives.

## Shape (A)

```
lease hunt(area × class)
        │
        ▼
resolve_hunt_perspectives(cfg)     # llm.hunt_perspectives, 2+ slots
        │
        ▼
for slot in perspectives:          # sequential; same tools, same path jail
    pack_hunt(+ perspective .md)
    tool loop → submit_candidate | submit_none
        │
        ▼
merge_hunt_candidates(slots)
        │
        ├─ all none → coverage last_depth=none (or shallow); optional requeue note
        └─ any candidate → insert best-ranked as state=candidate
                           enqueue validate_mech
```

### Config

```yaml
llm:
  hunt_perspectives:
    - id: sink_driven
      prompt: hunt_sink.md
      # model: null   # optional per-slot override; omit = llm.model / model_hunt
    - id: dataflow
      prompt: hunt_dataflow.md
    - id: authz
      prompt: hunt_authz.md

stages:
  hunt_moa: false   # default off until the wiring PR
```

- Resolver: `vulnforge/stages/hunt_moa.py` `resolve_hunt_perspectives` (same skip/default rules as `resolve_disprove_verifiers`).
- Built-in defaults match the list above when config omits it.
- Prompt files are **not** in this spike. Wiring PR adds `seeds/system/hunt_sink.md` (etc.) plus `pack_hunt(..., perspective=)`.
- Per-slot `model` is recorded when present (config hook only; no Settings picker in this spike).

Suggested lenses (prompt copy in PR2):

| id | Lens |
|----|------|
| `sink_driven` | Start from seed sinks / dangerous APIs; walk callers. |
| `dataflow` | Untrusted input → reachability (`query_flows` is heuristic, not taint). |
| `authz` | Missing/incorrect authorization vs documented trust boundaries. |

These are **perspectives on the same area×class**, not new hunt classes. Class skill body stays the skill; the perspective file is an extra lens, like `disprove_threat.md` vs `disprove_code.md`.

### Merge / rank (landed)

`merge_hunt_candidates(perspective_results) -> ranked list envelope`

1. **Identity:** cluster by `compute_stable_key` **and** `findings.merge.merge_key` (path + symbol). Exact keys and near-dupes collapse.
2. **Keeper:** richest body in the cluster (citations, evidence_id, threat_model, summary, poc_relpath). Extra titles stored as `near_dup_titles`.
3. **Rank:** `agree_count` desc, then evidence richness desc, then identity (stable).
4. **Cell:** all perspectives `submit_none` → `cell_outcome=none`, empty list. Any candidate → `cell_outcome=candidate`, keep **all** ranked clusters (caller inserts best, or best-N later). Spike tests require best-ranked to be the multi-agree cluster.
5. **Emit state:** every ranked item has `state="candidate"`. Input `body.state` is stripped. `result_emits_confirmed` walks the envelope.

### Invariant: merge never sets `confirmed`

- Automation paths that already insert findings use `state="candidate"` (`hunt.py` → `db.insert_finding(..., state="candidate")`).
- MoA merge **cannot** choose another state. `EMIT_STATE = "candidate"`. `_FORBIDDEN_EMIT_STATES = {confirmed}`.
- Human review / HITL (`vulnforge/hitl.py`, Report Accept) remain the only writers of `confirmed`.
- Dual disprove is demote-only (`needs_human` / `rejected_llm`). Hunt MoA is **propose-only** (`candidate`). Neither confirms.

Tests in `tests/test_hunt_moa.py` cover: both none; one candidate; two near-dupes merge; rank prefers multi-agree; poisoned `state=confirmed` input still emits `candidate`.

### Shallow / none cells (document; do not overbuild)

Existing `hunt.py` policy stays until wiring:

- Shallow `submit_none` requeues once with `force_depth` (`shallow_none_should_requeue`), unless operator forced none.
- Coverage `last_depth`: `shallow` | `none` | `candidate` | `aborted`.

MoA overlay (wiring PR, not this spike):

| Perspectives | Cell after merge | Requeue |
|--------------|------------------|---------|
| All `submit_none` | `none` (or `shallow` if the **lease** was shallow) | Keep today's shallow-once rule at **lease** granularity, not per slot. |
| Any candidate | `candidate`; keep best-ranked | Do **not** mark the cell none. Partial-none is a `requeue_note` only. |
| Mix of abort + none, no candidate | Treat as today's no_submit / abort path | Split ladder unchanged. |

`requeue_note` on the merge envelope is documentation for operators / later UX. Do not spawn extra child hunts from merge itself.

## Rejected alternatives

### B — Parallel hunt leases + merge task

Enqueue N `hunt` tasks (one per perspective) plus a join/`hunt_merge` kind.

**Rejected.** Default `max_leases_parallel: 1` means the siblings **queue**, they do not overlap. Wall clock is sequential anyway, plus:

- Duplicate `coverage_facts` races: each sibling `upsert_coverage_fact(..., visit_delta=1, last_depth=...)`. Last writer wins `last_depth`; visit counts inflate.
- Duplicate `insert_finding` before join: near-dup merge / `stable_key` upsert fights across tasks; a none-sibling can stamp `last_depth=none` after a candidate sibling stamped `candidate`.
- New task kind + join protocol is a bigger harness change than sequential slots (disprove already avoided this).
- Raising the lease cap just for hunt MoA contends with recon, validate, and operator tasks.

If an operator already runs N>1 workers, B still races coverage on the **same** area×class cell. A does not.

### C — Single hunt + diversify rewriter

One investigation, then a second LLM pass that rewrites/diversifies the same transcript.

**Rejected as the primary shape.** Weaker diversity: same tool trace, same missed sink. Keep as a **future hillclimb** if A lands and underperforms (cheap extra slot, no new lease story). Do not build it in the wiring PRs.

## Follow-up PR split (build A)

Build it. Split:

### PR1 — config + resolve/merge library

**This spike already lands the library, tests, and default-off config.** Follow-up only if review wants prompt *stubs* or a Settings readout of the flag before wiring.

### PR2 — `hunt.py` sequential perspective loop behind the flag

- Read `hunt_moa_enabled(cfg)`; if off, today's single `pack_hunt` + tool loop (no behavior change).
- If on: resolve slots; for each slot, pack with perspective markdown; run the existing tool loop; collect `{perspective_id, outcome, candidate|none_reason}` (do not insert per slot).
- After all slots: `merge_hunt_candidates`; **one** `insert_finding(..., state="candidate")` for the top ranked (or none); **one** coverage upsert; enqueue `validate_mech` only when a candidate exists.
- Transcript meta includes `perspective_id` (same idea as disprove `verifier_id`).
- Lease TTL / `max_tool_rounds`: either share the existing budget across slots or give each slot the current round cap. Recommend **share a total round budget** first so one lease cannot run 3× `max_tool_rounds` unnoticed. Document in PR2.
- Prompt files: `seeds/system/hunt_sink.md`, `hunt_dataflow.md`, `hunt_authz.md` + catalog rows in `docs/system/`. Shared hunt contract stays `PRINCIPLES.md` + class skill.
- Tests: FakeLLM sequential multi-response (copy `test_validate_llm_safety.py` / `test_pipeline_fake.py`); flag off golden path unchanged; flag on never inserts `confirmed`.

### PR3 — Report / Mission UX for multi-perspective hunt provenance

Only after PR2 writes provenance onto the finding body (e.g. `body.hunt_moa = {perspectives, agree_count, label}`).

- Report table: muted `2/3 hunt agree` (agreement is **not** verification and **not** confirm).
- Finding detail: per-perspective id, outcome, truncated reason / title.
- Mission / Hunts residual: optional note when `requeue_note` is `all_perspectives_none` vs `partial_none`.
- Absolute before/after screenshots required if UI changes (`docs/harness/validate/` style).

No Settings per-slot model picker in PR3 unless it is free with existing `validate_models` patterns. Config hook is enough.

## Non-goals (all follow-ups)

- Auto-confirm on 3/3 agreement.
- Multi-host model load/unload scheduler.
- War Room / chat-only MoA loops.
- Changing human-only confirm or HITL.
- Parallel sibling leases for the same cell.

## Open notes for PR2 (do not block this spike)

- **Budget:** shared `max_tool_rounds` vs per-slot. Start shared.
- **Evidence session:** each slot needs its own `write_evidence` (session auth is per tool loop). Merge keeps the keeper's `evidence_id`.
- **Same-model diversity** is weak signal (same honesty as dual disprove). Per-slot `model` is the config escape hatch; `llm.validate_models` is for validate, not hunt, unless PR2 deliberately reuses it.
- **continue_hunt / split** during a perspective: child is a full hunt task (flag on or off per child payload). Do not try to resume a mid-perspective slot across leases in v1.
